# Store Production Listing + Android Fastlane Release Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Get SevaRath (rider) and SevaRath Driver (driver) into real, public, compliant production listings on Google Play and the Apple App Store, with Android build+deploy fully handled by Fastlane (mirroring the iOS pipeline that already exists), and point the public download page at the new `sevarath-mobile` repo's releases instead of the pre-split `sevarath` repo's.

**Architecture:** Three independent phases. **Phase A** (no store accounts needed) repoints `sevarath`'s `/download` page at `sevarath-mobile`'s GitHub Releases and retires the 10 pre-split releases/tags that no longer correspond to any code in this repo. **Phase B** adds an `android` platform to the existing `tools/fastlane/Fastfile` (which today only has `platform :ios`), with one lane that replaces the raw `flutter build apk` calls in `release.yml` (sideload APKs, used by the download page) and one new lane that builds signed `.aab`s and pushes them to Google Play via `supply`/`upload_to_play_store`, reusing the existing keystore secrets. **Phase C** drafts and wires up the actual listing content both platforms require (descriptions, privacy policy, Data Safety/App Privacy answers, content rating, reviewer notes) and automates pushing the text portions via `fastlane supply`/`deliver`, using the existing App Store Connect API key for iOS and a new Play Console service account for Android.

**Tech Stack:** Flutter 3.47.6/.7, Fastlane (plain `gem install`, no Bundler — matches this repo's existing convention), GitHub Actions (`ubuntu-latest` for Android, `macos-15` for iOS — already proven), Google Play Developer API (via `supply`), App Store Connect API (via `produce`/`deliver`, reusing the existing `ASC_KEY_ID`/`ASC_ISSUER_ID`/`ASC_KEY_CONTENT_BASE64` secrets), a small React page added to `sevarath`'s existing Vite admin app.

**Spec:** none written separately — this session read `sevarath-mobile`'s existing `tools/fastlane/Fastfile`, `.github/workflows/{release,ios-testflight}.yml`, `android/app/build.gradle.kts`, `AndroidManifest.xml`, `ios/Runner/Info.plist`, `pubspec.yaml`, and `sevarath`'s `apps/admin/src/pages/Download.tsx`, `README.md`, `k8s/ingress.yaml`, and `docker-publish.yml` to ground every fact below. Two decisions were confirmed directly with the user in chat: **fully public (not unlisted) store listings**, and **a Play Console developer account already exists** (no new-account task needed).

## Global Constraints

- Bundle/application IDs stay exactly `com.rajendrakhope.sevarath` (rider, app name "SevaRath") and `com.rajendrakhope.sevarath.driver` (driver, app name "SevaRath Driver") on both platforms — identical to what's already shipping, so every store record is additive, not a rename.
- Android's existing keystore-based signing (`android/key.properties` written from the `ANDROID_KEYSTORE_BASE64`/`ANDROID_KEYSTORE_PASSWORD`/`ANDROID_KEY_ALIAS`/`ANDROID_KEY_PASSWORD` GitHub secrets) is reused as the Play **upload key** — not replaced. Google Play App Signing re-signs with its own key on top of it; no new Android signing material is generated by this plan.
- iOS's existing `match`-managed signing and `ASC_KEY_ID`/`ASC_ISSUER_ID`/`ASC_KEY_CONTENT_BASE64`/`MATCH_PASSWORD`/`MATCH_GIT_BASIC_AUTHORIZATION` secrets are reused as-is for App Store Connect API calls (`produce`, `deliver`) — no new Apple credentials.
- The app has **no payment, fare, surge pricing, or wallet feature** (confirmed in `sevarath/README.md` — "no payment, fare calculation, surge pricing, wallet, or commercial transaction"). Every piece of listing copy, the content-rating answers, and the Data Safety/App Privacy answers in this plan reflect that — none may claim or imply monetization, ads, or in-app purchases.
- Per the user's explicit choice: both listings are **fully public and discoverable** on their respective stores, not Google Play "Unlisted" or Apple "Unlisted App" distribution — but the copy still describes the app honestly as a ride service for the Shantivan (Abu Road) campus community, not generic consumer taxi marketing.
- Android release artifacts: `.apk` (signed, for the GitHub-Release sideload path the download page serves) **and** `.aab` (signed, mandatory for any new Play Store app) are both produced from the same Fastlane lanes family — Play Store itself never accepts a raw `.apk` for a new app.
- No secret value (keystore passwords, the new Play service-account JSON, the Apple `.p8` key) is ever typed into a chat message or committed to git. Every step that touches one is marked **Owner: You**, with the exact `gh secret set`/console command to run, consistent with how the existing Apple secrets were set up (see `docs/secrets/readme.md`).
- Every new Fastlane lane is invoked the same way the existing `fastlane ios ci_release` is — `fastlane <platform> <lane>` from `tools/fastlane`, with CI installing Fastlane via plain `gem install fastlane --no-document` (no `Gemfile`/Bundler exists in this repo, and that's intentional per `tools/fastlane/README.md`'s auto-generated note and the as-built history in `docs/mobile-plan.md`).
- `flutter analyze` and `flutter test` must keep passing unmodified — this plan touches native Android/iOS config, Fastlane, CI YAML, and the separate `sevarath` admin React app, not Dart application code.

## Review Focus

1. **Reviewer's device isn't on campus.** `lib/core/config/campus_config.dart` enforces a hard ~2000m service radius around `LatLng(24.5313075, 72.7947805)` (Diamond Hall Shanti Van, Abu Road) — a real device at Apple's or Google's review facility is thousands of kilometers outside it and will hit "You're too far from campus" the moment it tries to book, with no way to see the app's actual core feature. Task C5 gives both stores' reviewers exact coordinates and spoofing instructions in the official review-notes field — without it, rejection at first login/booking attempt is near-certain.
2. **Play Store's very first release of a brand-new package name cannot be created via the API at all.** `upload_to_play_store` (`supply`) fails outright against an app that has zero manually-uploaded releases — this is a hard Google Play restriction, not a bug in this plan's lane. Task B3 is the one-time **Owner: You** manual upload, once per package name (two apps), that the CI lane in Task B4 depends on forever after.
3. **A static build number silently gets rejected on the second push.** Both Play Store (`versionCode`) and TestFlight (already fixed for iOS in `tools/fastlane/Fastfile`) require each package's build number to strictly increase across uploads — `pubspec.yaml`'s unchanging `0.0.1+1` would make the *second* `release_playstore` CI run fail with "version code already used," exactly the class of bug the iOS lane's own comments call out as already fixed there. Task B1's Android lane needs the same `GITHUB_RUN_NUMBER`-based `--build-number` override.
4. **Login-gated app, no public content to show without an account.** Both `com.rajendrakhope.sevarath` and `com.rajendrakhope.sevarath.driver` require Firebase Auth/Google Sign-In before anything else renders. A reviewer with no credentials rejects at the login screen having seen nothing. Task C5 also covers providing one working demo account per app.
5. **Declared data types must trace to real code, not boilerplate.** Play's Data Safety form and Apple's App Privacy "nutrition label" are both subject to takedown for a declaration that doesn't match the binary's actual behavior. This plan's answers in Task C4 are derived from the actual permissions/dependencies found in this codebase — `ACCESS_FINE_LOCATION`/`ACCESS_COARSE_LOCATION` + `geolocator` (location), `firebase_auth`/`google_sign_in` (name, email), `firebase_messaging` (device token for push) — and deliberately say "no" to analytics, ads, and tracking, because no such SDK exists in `pubspec.yaml`.

### Task B1: Add the `android` platform to the Fastfile

**Owner: Agent**

- [ ] **Step 1: Append the Android platform block**

Add to the end of `tools/fastlane/Fastfile` (after the `platform :ios` block's closing `end`):

```ruby
platform :android do
  desc "CI: build both flavors' signed release APKs into dist/, named for a GitHub Release"
  lane :build_apk do |options|
    tag_name = options[:tag_name] || ENV.fetch("TAG_NAME")
    dist_dir = File.join(REPO_ROOT, "dist")
    FileUtils.mkdir_p(dist_dir)

    {
      "user" => {
        target: "lib/main_user.dart",
        built_name: "app-user-release.apk",
        dest_name: "SevaRath-#{tag_name}.apk"
      },
      "driver" => {
        target: "lib/main_driver.dart",
        built_name: "app-driver-release.apk",
        dest_name: "SevaRath-Driver-#{tag_name}.apk"
      }
    }.each do |flavor, cfg|
      Dir.chdir(REPO_ROOT) do
        sh(
          "flutter", "build", "apk",
          "--release",
          "--flavor", flavor,
          "-t", cfg[:target],
          "--dart-define=API_BASE_URL=https://sevarath.rajendrakhope.com/api/v1"
        )
      end

      FileUtils.cp(
        File.join(REPO_ROOT, "build", "app", "outputs", "flutter-apk", cfg[:built_name]),
        File.join(dist_dir, cfg[:dest_name])
      )
    end
  end

  desc "CI, upload: build both flavors' signed AABs and push to Google Play (binary + version bump only - no metadata/images, see upload_play_metadata)"
  lane :release_playstore do |options|
    track = options[:track] || ENV["PLAY_TRACK"] || "internal"
    # Same reasoning as iOS's ci_release: Play rejects a reused versionCode on the
    # second upload for a package, and pubspec.yaml's version is static.
    build_number = ENV["GITHUB_RUN_NUMBER"] || Time.now.to_i.to_s

    {
      "user" => { package_name: "com.rajendrakhope.sevarath", target: "lib/main_user.dart" },
      "driver" => { package_name: "com.rajendrakhope.sevarath.driver", target: "lib/main_driver.dart" }
    }.each do |flavor, cfg|
      Dir.chdir(REPO_ROOT) do
        sh(
          "flutter", "build", "appbundle",
          "--release",
          "--flavor", flavor,
          "-t", cfg[:target],
          "--build-number", build_number,
          "--dart-define=API_BASE_URL=https://sevarath.rajendrakhope.com/api/v1"
        )
      end

      aab_path = Dir.glob(
        File.join(REPO_ROOT, "build", "app", "outputs", "bundle", "#{flavor}Release", "*.aab")
      ).first
      UI.user_error!("No .aab found for the #{flavor} flavor") unless aab_path

      upload_to_play_store(
        package_name: cfg[:package_name],
        aab: aab_path,
        track: track,
        json_key_data: ENV.fetch("PLAY_STORE_JSON_KEY"),
        skip_upload_metadata: true,
        skip_upload_images: true,
        skip_upload_screenshots: true
      )
    end
  end

  desc "Local/manual: push Android store-listing text for both apps from tools/fastlane/metadata/android - no binary, no version bump"
  lane :upload_play_metadata do
    {
      "user" => "com.rajendrakhope.sevarath",
      "driver" => "com.rajendrakhope.sevarath.driver"
    }.each do |flavor, package_name|
      upload_to_play_store(
        package_name: package_name,
        json_key_data: ENV.fetch("PLAY_STORE_JSON_KEY"),
        metadata_path: File.join(REPO_ROOT, "tools", "fastlane", "metadata", "android", flavor),
        skip_upload_apk: true,
        skip_upload_aab: true,
        skip_upload_images: true,
        skip_upload_screenshots: true
      )
    end
  end
end
```

### Task B4: CI workflow for Play Store releases

**Owner: Agent**

**Files:**
- Create: `.github/workflows/android-playstore.yml`

- [ ] **Step 1: Write the workflow**, mirroring `.github/workflows/ios-testflight.yml`'s structure and `release.yml`'s signing-secret setup:

```yaml
name: Android Play Store Release

on:
  push:
    branches: [main]
    paths:
      - 'lib/**'
      - 'android/**'
      - 'tools/**'
      - 'assets/**'
      - 'pubspec.yaml'
      - 'pubspec.lock'
      - '.github/workflows/android-playstore.yml'
  workflow_dispatch:
    inputs:
      track:
        description: 'Play Store track to release to'
        required: false
        default: 'internal'
        type: choice
        options: [internal, alpha, beta, production]

permissions:
  contents: read

concurrency:
  group: android-playstore
  cancel-in-progress: true

jobs:
  build-and-upload:
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '21'

      - uses: subosito/flutter-action@v2
        with:
          flutter-version: '3.47.6'
          channel: stable

      - run: flutter pub get

      - name: Set up release signing
        env:
          ANDROID_KEYSTORE_BASE64: ${{ secrets.ANDROID_KEYSTORE_BASE64 }}
          ANDROID_KEYSTORE_PASSWORD: ${{ secrets.ANDROID_KEYSTORE_PASSWORD }}
          ANDROID_KEY_ALIAS: ${{ secrets.ANDROID_KEY_ALIAS }}
          ANDROID_KEY_PASSWORD: ${{ secrets.ANDROID_KEY_PASSWORD }}
        run: |
          echo "$ANDROID_KEYSTORE_BASE64" | base64 -d -i > android/app/upload-keystore.jks
          cat > android/key.properties <<EOF
          storeFile=upload-keystore.jks
          storePassword=$ANDROID_KEYSTORE_PASSWORD
          keyAlias=$ANDROID_KEY_ALIAS
          keyPassword=$ANDROID_KEY_PASSWORD
          EOF

      - name: Set up Firebase config
        env:
          GOOGLE_SERVICES_JSON: ${{ secrets.GOOGLE_SERVICES_JSON }}
        run: echo "$GOOGLE_SERVICES_JSON" > android/app/google-services.json

      - uses: ruby/setup-ruby@v1
        with:
          ruby-version: '3.3'

      - name: Install fastlane
        run: gem install fastlane --no-document

      - name: Build both flavors and upload to Play Store
        working-directory: tools
        env:
          PLAY_STORE_JSON_KEY: ${{ secrets.PLAY_STORE_JSON_KEY }}
          PLAY_TRACK: ${{ inputs.track || 'internal' }}
        run: fastlane android release_playstore
```
